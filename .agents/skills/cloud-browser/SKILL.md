# Architecture

Each user workspace has two independent cloud slots: one file preview and one web browser. A slot is shared by the user and their chats. Its mode stays fixed for its whole life. Web sessions hold up to eight tabs. The agent's tab and the viewer's selected tab are separate. The local Preview starts no cloud use. Playwriter is a separate connection to one confirmed native tab, with no app video viewer.

Both web providers apply the current `BROWSER_WEB_DENIED_HOSTS` list and saved user site blocks. Each new Playwriter command also checks the current allowed extension versions. Old receipts and cleanup still work after a version is removed.

Playwriter uses the user's signed-in browser profile and own network. Production permits Press hosts, so the agent can act as that user across their organizations. It can also reach localhost, private-network, and intranet pages. This accepted policy has no cloud-provider network boundary. See the remote reference for the full rules.

In file mode the page loads local file bytes, snippets cannot navigate or open pages, popups are blocked, and only `esm.sh` escapes the sandbox.

- The runner owns the provider browser, snippet isolation (Dynamic Worker), leases, deadlines, and the viewer gateway. The Convex app never touches provider credentials.
- Cloudflare guardrails own the network allowlist outside snippet code. A blocked navigation can change `page.url()` while returning a 403 guardrails page; check the response status and headers before calling it a network escape. The runner checks the registered page after command errors too and closes it if the check fails.
- A session loads exactly one file and source kind (`saved`, `proposed`, `draft`). It keeps running when the user leaves the Browser view or opens another file, a folder, or the root; only End, the idle and total limits, and access loss end it. Coming back to its file shows the same live page with no new Start. Edits only raise the Updates badge. Switching kinds needs a new Start. Reload re-reads the same kind (drafts need a fresh editor capture first, taken with the session's own `navigationGeneration`).
- Control states: `starting`, `ready` (agent may act), `agent` (command running, runner-side only — the doc stays `ready`), `pausing` (take during a run), `human`, `closing`, `closed`. Each command checks its exact generations (`navGen`, `loadGen`, `controlGen`). A successful agent reload advances the turn binding only to the generations returned by that reload, including the exact web `tabId` and `tabGen`. It gives the model a fresh private browser result. It never adopts another live session or takeover.
- Detaching the last input holder releases its input but keeps human Pause. Only Resume returns control to `ready`. A stale command closes its browser: a lost caller does not prove its work stopped. Every host run path finishes its command (`try/finally`); duplicates are harmless.
- Each agent command has one durable connection grant. The child sees an app session id, never the provider id. The trusted protocol bridge allows only the assigned page and its attached frames and dedicated workers. Service workers, shared workers, and worklets are resumed and detached without a session for the child. It refuses provider methods, raw CDP attachment, target creation, protocol tunnels, downloads, and provider file paths. Normal page actions, screenshots, and context tracing remain supported.
- Before returning output, the runner revokes the grant, drains accepted protocol calls, removes command scripts/bindings, and releases held input. It then checks Chromium's target/context inventory plus the controller URL and nonce. Only a settled command may release its lock. Lost or uncertain cleanup closes that exact browser; a restart cannot reuse an unproven connection.
- The trusted connection watches page navigation and popups for the whole session, including timers left after a command. Main-page navigation closes the session unless it belongs to a trusted reload. Popups close without ending the assigned page. Reconnect checks the full target/context inventory, controller URL, and nonce after installing listeners. Reload waits for that check and uses the same connection. An admitted reload failure closes that exact session because navigation may already have changed the page.
- A child socket close or error revokes new commands but leaves the provider connection open for draining and cleanup. Provider errors and failed cleanup close the session. The host still closes on isolate timeout or missing results.

# Web Mode

Route `/w/$org/$ws/browser` (sidebar "Browser", `components/browser/web-browser.tsx`, shared `components/browser/browser-viewer.tsx`). It is not tied to a file. It restores the owner's saved logins for that workspace (see Saved Logins).

- Network: web sessions acquire with **no guardrails** (guardrails are allowlists only). The provider's egress proxy refuses private and metadata addresses with a 403, and Chrome blocks loopback (checked live on 2026-09-23). The runner var `BROWSER_WEB_DENIED_HOSTS` (dev: our app, Convex, Clerk, and Worker hosts; production: empty) is UX and loop protection, not a network boundary. Every navigation we start goes through `browser_web_normalize_url` in `packages/common/src/browser-web-url.ts`: `http:`/`https:` only, no user or password, no denied host.
- Open order: acquire, check one context and one page, save the record as `starting`, connect the host, set the viewport, restore the saved profile, navigate to the start address when there is one (a slow or failing site does not fail the open), then `ready`. A refused start address never acquires a browser (`address_blocked`).
- `loadGen` never changes in web mode. Page navigation does not end the session and does not extend idle. The host pushes `{t:"location"}` on main-frame navigation.
- Popups: when no agent command runs, a valid popup becomes a registered tab within the eight-tab limit. A blank popup gives `popup_closed`, and a denied address gives `address_blocked`. During an agent command it only closes (`popup_closed`). File choosers and downloads: see Downloads And Uploads.
- Agent access: a saved user/workspace setting in `files_browser_preferences`, shared by both web providers. It defaults to cloud with access on. Choice changes raise `selectionRevision`; access or blocked-site changes raise `policyRevision`. Settings sync to live runners. Off revokes running work and blocks new work. Opening a browser never turns access on. File previews do not use this web setting.
- Every active member can read their own saved choice and revisions for Chat. This grants no browser use. Browser tools and settings writes still need `workspace.browser.use`.
- Bridge (web): allows `Page.navigate` (same URL rules), `Page.reload`, history navigation, and `Page.stopLoading`. It answers `Browser.setDownloadBehavior` itself without forwarding it, forces `grantUniveralAccess` off, and removes cookie, set-cookie, authorization, and proxy-authorization headers plus cookie lists and raw `headersText` blocks from every forwarded Network event (both modes). `Page.navigate` to a site on the agent's blocked list is refused with `agent_blocked_site`. Cookie, storage, and Fetch methods stay refused.
- Known limits of the bridge: the agent cannot get cookie headers or cookie CDP data, but it can read tokens a site puts in a response body or page text. Agent code can also leave a listener or a patched `fetch` in the page after its command ends, so a password typed later on that page is exposed. Take control does not reload the page (that would drop the user's form state).
- Busy: a second agent command while one runs gets `busy_command`; the chat shows "Another chat is using the browser. Try again later." A command during a reload and other refusals get plain `busy` from the runner; the tool then shows the generic `execution` error "The browser command could not finish."
- Who may start: cloud file and web sessions need `workspace.browser.use` and a paid payer plan. Playwriter needs that permission but no paid plan; it uses the user's computer and creates no cloud-browser usage charge.
- Billing: the runner writes a usage receipt `{providerAcquiredAt, endedAt, reason}` in `release_closed_session`, so every close path writes one (none when nothing was acquired; pruned after 7 days). `status` returns `{alive:false, closing, usage, profileStored}` (`profileStored` is true while saved cookie bytes exist; QA reads it) and `close` returns `usage`. Convex settles once per session in `settle_browser_usage`: 0.3 credit cents per started minute, one `browser_usage` event to the frozen `billedUserId`. With no receipt it waits 10 minutes, then bills 0 and logs `browser_usage_missing`. End during Start is billed too: the commit fails, the doc keeps its `runnerSessionId`, and the start door settles from the close reply. A failed open after acquire is not billed (rare). A 5-minute cron settles docs that ended without a settle; a doc that cannot settle yet gets a new `updatedAt`, so 50 stuck docs cannot block the batch. The 7-day sweep deletes settled docs only.
- Access loss: removing a member schedules `end_browser_session_internal` for their live browsers in that organization, and the 5-minute cron first closes live web sessions whose owner lost membership or `workspace.browser.use`.
- Start texts: `user_limit` / `organization_limit` have their own messages, and a session still closing shows "The last browser is still closing. Try again in a minute." The Start card stays on screen (with the typed address and any refusal) until the session is `ready`. Tool cards use reasons `busy` ("Another chat is using the browser. Try again later."), `agent_access_off` ("The user turned off agent access to this browser."), and `agent_blocked_site` (see Saved Logins); the model is not told to retry after `agent_access_off`.

# Downloads And Uploads

Web mode only. The runner does this on the host connection; the agent bridge still refuses `Fetch.*` and downloads. Details and route shapes: `packages/browser-runner/README.md` "Downloads and uploads".

- Capture: one `Fetch.enable` always holds a Response-stage `Document` pattern (plus the agent blocked-sites Request-stage filter during commands). A response with `Content-Disposition: attachment`, or a type not in the runner's explicit shown list (`SHOWN_CONTENT_TYPES` plus `audio/*` and `video/*`; so `text/csv` and `image/tiff` download), is read with `takeResponseBodyAsStream` + `IO.read` (1 MiB chunks), then ended with `Fetch.failRequest("Aborted")` (Chrome refuses `fulfillRequest` after the body is taken). The page stays. Every pause is answered in `try/finally`. PDF shows inline. Safety net: `Browser.setDownloadBehavior({ behavior: "deny", eventsEnabled: true })`; on `downloadWillBegin` a `data:` URL is decoded and a same-origin link is re-read in an isolated world; anything else gets `download_unsupported`. `blob:` downloads give no event and are not supported.
- Who: human control plus a click, Enter, or address Go in the last 10 s, main frame only, one download per gesture → human download. During an agent command → agent download. Anything else (page timers) → dropped with `download_blocked`. Known limit (accepted 2026-09-23): the click does not have to be the one that caused the download, so a page script can start one download within 10 s of any human click. It is still one file per gesture, names are normalized and never replace a file, and the toast shows each saved file with Delete. When the server sends no file name, the last URL path segment becomes the name, so avoid downloading from secret-in-path links in a team workspace.
- Caps: human 25 MiB, agent 8 MiB per file; 20 files and 100 MiB per session; one capture at a time; 3 starts per 10 s; one unclaimed human download. Notices: `download_too_large`, `download_limit`, `download_busy`, `download_failed` (read error, a capture over 30 s, or a body whose size differs from `Content-Length` when there is no `Content-Encoding`), `download_lost` (unclaimed for 2 minutes or at close).
- Human download: the runner holds the bytes and pushes `{t:"download", downloadId, name, size, contentType}`. The UI calls `save_browser_download` at once. Convex asks `download-info`, creates the node in `/.system/downloads/` (created when missing, never replaces, `-2` suffixes, `readme`/`agents`/`skill` get `-download`), stores `source: browser-download` and `original-url` = the download URL's origin only, and signs a PUT URL; the runner `download-push` PUTs the bytes and the normal R2 finalizer publishes the file. Idempotent per `(sessionId, downloadId)` through `files_browser_download_saves`. A failed push can be retried: the error toast has Retry, which saves again while the runner still holds the bytes. In a team workspace every member with read access sees it; the toast says so. A viewer that says hello again gets the waiting download and the open chooser again, so a reconnect loses neither; saves are idempotent. The 2-minute expiry waits for a running push.
- Agent download: returned in the run result `downloads`, sharing the 8 items / 8 MiB limit with emitted files; becomes a pending file (see Agent Tools).
- Uploads: `Page.fileChooserOpened` with a `backendNodeId` in human control stores one chooser (bound to `controlGen`, the main-frame navigation count, and the frame origin; 5-minute life) and pushes `{t:"file-chooser", chooserId, multiple, accept, origin}`. During agent commands the snippet handles its own chooser. From Files: `fill_browser_chooser_from_files` checks `content.read` per node and signs 5-minute GET URLs; the runner `upload-fill` fetches at most 20 MiB and calls `setFiles`. From the computer: `grant_browser_upload` gets a single-use 2-minute grant; the browser `PUT`s one raw file to `runner/viewer/upload` (CORS only for `BROWSER_APP_ORIGINS`); the runner stores nothing. One fill per chooser. Cancel (`file-chooser-cancel`) fires the input's `cancel` event. No `backendNodeId` (for example `showOpenFilePicker`) → `upload_unsupported`. `upload-fill` reads the files in parallel under one 20 MiB cap and ends within 120 s (`fetch_failed` past it); Convex waits 150 s and signs 5-minute URLs. The fill re-checks the chooser right before `setFiles`. A failed computer upload replies `upload_failed` with CORS headers (UI: "The file could not be sent to the page. Try again."). The runner sends `file-chooser-closed` before `setFiles`, so a fill refusal can arrive after the dialog closed. The dialog shows a refusal inline while it is open; after it closed, the panel shows it as a toast.

# Saved Logins

Web sessions keep the owner's logins in one saved profile per user and workspace. The runner stores the cookies encrypted. Convex holds only the key half and never sees cookie names or values. Site names pass through `list_browser_profile_sites` for the owner but are never stored or logged.

- `files_browser_profiles` holds the private `profileKey`, `createdAt`, and `lastUsedAt`. A web start updates `lastUsedAt` and sends the key to the runner. Blocked hosts live in `files_browser_preferences`, separate from cookies and provider choice. No public result or log carries the profile key.
- Doors: `current_browser_profile` reports saved-data presence and last use. Listing or clearing saved sites ends only the live web slot, then calls the checked profile route. Clear all deletes the profile and key. These owner actions do not need `workspace.browser.use`. Blocked sites are edited in Browser settings through `set_agent_blocked_hosts`; they apply to live web providers after checked sync. Removing cookies does not reset those settings.
- Runner storage (`packages/browser-runner/src/index.ts`, tests in `profile.test.ts`): AES-GCM with a key made from the Worker secret `BROWSER_PROFILE_KEY` plus `profileKey`; the extra data binds profile, owner, organization, and workspace, so bytes moved to another profile do not open. The key lives only in Durable Object memory, so after a restart no save happens until the next open. Restore runs in `open` before the first navigation (`Storage.setCookies` without a context id); any failure starts empty. Save happens on human End (`saveProfile: true`), on idle or total expiry, and on a viewer renew when human input (address bar navigation included) or an agent command changed the page and the last save is over 2 minutes old. It never happens on security, internal, or agent closes. A save drops cookies of hosts in `BROWSER_WEB_DENIED_HOSTS`. Caps: 3,000 cookies and 1 MiB (`truncated`); session cookies and the longest-lived cookies are kept first. A save re-reads the `profileDeleted:<id>` tombstone right before it writes, so a save racing a delete never brings the cookies back. An older save that finishes after a newer one (for example the End save) skips its write. `schedule_alarm` is the only alarm writer; it covers the session deadlines, the 100-day profile delete, and the 7-day tombstone cleanup.
- Runner refusals come back with their code: `busy` while a session is live or when the stored cookies changed during a clear (try again). `profile_unreadable` becomes "Saved data could not be read. Clear all to start fresh."
- Settled agent work also saves dirty cookies after the two-minute save interval, even with no viewer. Agent Close still does not save cookies.
- Delete: every path goes through `files_browser_db_delete_profile`. It deletes the doc and writes a `files_browser_profile_wipes` doc in the same transaction. Without the key the cookies cannot be read from that moment. Callers schedule `process_browser_profile_wipes`, and a 5-minute cron runs it too. It calls runner `profile-delete`, which also closes a live session with that profile. It works while web mode is off and while the runner kill switch `BROWSER_RUNNER_DISABLED` is on. A failure waits 1 minute, doubling each time, up to 6 hours, with no attempt limit, and logs only `browser_profile_wipe_failed` with `attempts`. The runner deletes the bytes by itself 100 days after the last save, as the last backstop.
- Deletion paths: Clear all, 90 days without a web start (hourly cleanup), member removal (their profiles in that organization), workspace purge, the account deletion request (closes live browsers and runs `delete_user_profiles_batch`, which continues itself until done), and the data-only reset.
- Blocked sites: the runner refuses `browser_run` with `agent_blocked_site` while the page is on a listed site, before or after the command, and drops that command's output. The tool card and the model get "This site is on the list of sites the agent may not use." The model is not told to retry. The runner enforces the list on a best-effort basis.

# Convex Doors

- `start_browser` (action): explicit Start only; reattaches the same live file/source/nav generation, otherwise `Browser busy`. Draft bytes arrive through `capture_browser_draft` + storage upload + `attach_draft_capture_blob`.
- `start_web_browser` (action): web mode Start. It needs the flag, `workspace.browser.use`, and the payer's paid plan. A repeated start reuses the live web slot before new-start limits and ignores a new start address. A live file slot stays open. `web_browser_available` returns `{ enabled, paidPlan }` for the Start card. Agent start uses `agent_open_browser` with its exact original user-message source, saved intent, and durable command identity.
- Start and failed viewer grants/renewals ask the runner whether the session is still alive. Status and renew include current source/control generations and deadlines. Convex copies these values; it does not invent load generations. Source and control merge separately, so delayed replies cannot undo a newer load, tab navigation, or takeover. Tab catalogs keep newer saved generations for each matching tab ID. Their control, policy, and selection checks still gate tab additions and removals. Confirmed loss retires the app doc so Start can recover. An old mirrored idle deadline alone does not prove loss: human input can extend it at the runner.
- `current_browser_session({membershipId,mode})` (query): the owner's live session in that slot or null. `browser_source_current_version` feeds the Updates badge.
- `grant_browser_viewer` / `renew_browser_viewer`: single-use short grants plus the socket URL. Renew re-checks access on a timer; refusal closes the stream. The app renews every 20 s and the runner grant lasts 90 s, so a background tab whose timer runs once a minute keeps its stream. The trade-off: a modified client that stops renewing keeps watching and typing for up to 90 s after its last renew. Member removal, account deletion, and every close end the stream at once; a removed `workspace.browser.use` waits for the next renew or the 5-minute access cron. Renew also mirrors runner-led control changes (detach release, pausing finish) back to the session doc.
- `take_browser_control` / `resume_browser_agent` hand off the exact session. Resume requires the `controlGen` shown to the user. A late Resume cannot release a newer Take. It does not depend on a selected chat. Human New and Close Tab require the viewer's `viewerId`; the runner checks the current input holder. A refused Close keeps the live session and pending billing, even when its reply has no session metadata. Other controls are `reload_browser`, `keep_open_browser`, and `end_browser`.
- Agent reload and close carry `expectedAgentLease` through Convex to the runner. The runner checks ready control plus the frozen control/load/navigation generations before accepting them. Take during an accepted reload waits for it to finish; an overdue reload closes the page before input can resume. Human buttons omit the agent-only guard.
- Viewer-side doors re-check live access through `authorize_live_browser_session` and close the session on loss (`end_browser_session_internal`, reason `access_lost`). File mode checks file access (revoke, archive, delete, type change). Web mode checks `workspace.browser.use`; web mode turned off (`Browser unavailable`) does not close the session here. The agent's check is the internal query `check_browser_session_access`, run before and after each `browser_run`. It refuses (`closed`, `denied`, `agent_access_off`) without closing.
- File output uses thin internal `prepare_file_output` and `finalize_file_output` doors. They call the shared `files_ingestion` backend. Files owns paths, collision names, text or stored content, reservations, retry receipts, and cleanup. Fresh prepare and finalize check the browser source and exact lease in the same transaction. A completed retry needs current Files read access but no live browser. Abort retires only unfinished work. Stored holds remain until exact-key deletion settles after the last possible PUT.
- Cleanup: the hourly browser cron deletes expired draft captures, unfinished starts, old daily counters of both tables, settled sessions after their retention, and saved profiles unused for 90 days. Screenshots follow normal Files expiry, Discard, Save and purge. Saved screenshots stay until deleted.
- Human downloads (web only): `save_browser_download({membershipId, sessionId, downloadId})` → `{nodeId, path, shared}` (`shared` = not the default personal organization). Owner, live web session, and the live source check. Order: `files_browser_download_saves` lookup (a pushed save returns its node and the runner is not asked), runner `download-info`, internal `create_browser_download_node`, runner `download-push`, internal `mark_browser_download_pushed` (sets `pushedAt`). When `download-info` says `download_gone`, the door looks at the save doc again: another viewer tab may have pushed the download meanwhile, and then its file is the answer. The mutation re-checks the session and the save doc, then applies the `files_tree_write` rate limit and the payer's paid plan ("Download not saved: your plan no longer allows the browser."). It creates a normal upload node at `/.system/downloads/<name>` (folder made on demand, name from `files_normalize_browser_download_name`, never replaces: `-2`, `-3` among saved files), with metadata `source: browser-download` and `original-url` = origin only (re-derived from the runner reply; omitted for `data:`). It inserts the save doc (`pushedAt: null`) in the same transaction and returns a 15-minute signed PUT URL; the normal R2 finalizer publishes the file. A save doc found with `pushedAt: null` gets a new signed PUT URL for the same asset, so a second tab or a retry pushes again; the runner joins a running push, and `If-None-Match: *` keeps the first upload. `download_gone` → "Download not saved: it is no longer available."; `download_push_failed` → "Download not saved: the upload failed." A failed push keeps `pushedAt: null`, so a retry of that `downloadId` pushes again while the runner holds the bytes (2 minutes). If nobody retries, the empty upload node goes to the normal unfinalized-upload cleanup.
- File choosers (web only): fill and upload grants require `{membershipId,sessionId,chooserId,controlGen,tabId,tabGen,viewGen}`. `fill_browser_chooser_from_files` also takes 1–10 `nodeIds`. It signs a five-minute GET URL per readable file and sends `{name,contentType,url}` to `upload-fill`. A folder, unreadable file, or total above 20 MiB refuses the whole call. `grant_browser_upload` returns `{url,expiresAt}`. Its `/viewer/upload` URL carries `ownerId`, `organizationId`, `workspaceId`, `mode`, and `grantId`; the client adds `name`. The runner checks the exact chooser, tab, view, and human control. Its refusal codes pass through in `_nay.name`. A late fill reply clears only its own chooser; a newer chooser and its picks stay open.
- Every session delete goes through `browser_db_delete_session`, which deletes the session's `files_browser_download_saves` docs too. The saved files stay; they are ordinary Files nodes.

# Viewer Protocol

- WebSocket `/viewer/stream` carries non-secret `ownerId`, `organizationId`, `workspaceId`, and `mode` query fields to select the right slot. The first JSON hello repeats that scope, plus `grantId` and `host: docked | detached`, within 5 seconds. The reply includes `viewerId`, viewport, control, `controlGen`, mode, tab identity, the tab list, and policy/selection revisions. No provider credentials or raw CDP surface reach the client.
- One shared CDP screencast produces JPEG frames for all viewers. Each `{t:"frame",seq,loadGen,tabId,tabGen,viewGen}` immediately precedes its binary JPEG. The client sends `{t:"frame-ack",seq}` after the frame callback, including on callback failure before closing. This confirms delivery, not decode or paint. Each viewer has at most two frames in flight. ACKs match the oldest first. Only the latest waiting frame is kept, so a slow viewer cannot block others. A new viewer gets the cached frame on a static page.
- `{t:"control"}` pushes control changes. `{t:"viewport", viewport}` precedes frames for a new load or size. Binary frames need adjacent valid metadata; viewport changes and close clear pending metadata. The producer applies the stored viewport. Start and stop are serialized; reload, viewport changes, and a completed agent command on the viewed page restart it. Agent tracing can replace the screencast, so the command stays locked through restart and a fresh session check before handoff.
- Client input is `{t:"input",seq,controlGen,loadGen,tabId,tabGen,viewGen,kind,...}` (`mouse.move/click/down/up`, `wheel`, `key.press/down/up/type`). The client uses its observed control and last delivered image identity. One ordered queue checks that identity and the durable lease, saves activity, and re-checks control before Playwright. It replies with `{t:"input-ack",seq,ok,timings}`. Only moves to the last applied position are skipped after authorization. Take, Resume, Reload, agent begin, and input-holder detach reject stale queued input, drain current input, and release held buttons and keys. Input failure or timeout closes the session. Close invalidates queued input and ends the page.
- Authenticated viewers may send `{t:"ping", seq}` once per second. The reply is `{t:"pong", seq}`. This reads no storage, calls no provider, and extends no deadline. Use it to separate socket latency from input work.
- Web navigation uses `{t:"nav",seq,controlGen,tabId,tabGen,viewGen,action:go|back|forward|reload|stop,url?}` with the input queue and `{t:"nav-ack",seq,ok,code?}` reply. Tab selection has its own viewer generation. Web also adds `text.insert`, file-chooser controls, location/access notices, downloads, and chooser events. Tab, location, viewport, and chooser events carry their tab/view identity. File viewer identity uses `sessionId` as `tabId`, `navGen` as `tabGen`, and `loadGen` as `viewGen`. Full shapes: `packages/browser-runner/README.md`.
- The last viewer leaving stops the producer. Detach writes are ordered; command finish and reload wait for that cleanup before saving. Provider failure during held or in-flight input ends the session. Grant and session deadlines close sockets even without frames. Close codes: 4401 bad grant, 4404 session gone, 4408 grant expired, 1011 stream failure.
- The trusted Playwright connection remains open for input and command checks. Stream restarts use a new CDP session, so old frames cannot cross a load boundary. Viewport restore writes trusted device metrics explicitly because Playwright's cached size may miss another connection's changes.

# Agent Tools

`browser_status`, `browser_open`, `browser_tabs`, `browser_new_tab`, `browser_close_tab`, `browser_run`, `browser_reload`, and `browser_close` work without a mounted Browser panel. Status and Open return private browser references. Web Run and Reload use both `browserRef` and `tabRef`. File mode uses only `browserRef`; omit `tabRef` or use JSON null, never the string `"null"`. Close ends the whole session and takes only `browserRef`. Run also takes up to 20 KB of code and supplies `page`, `frame`, `expect`, and `emitFile`. Use `frame` for file content. A turn allows 20 browser operations across providers. Remote fixed tools are described in [Playwriter](references/playwriter.md).

Agent Open keeps the control admitted before reuse, or returned by its own new runner Open. A human Take and Resume during an awaited read makes Open stale and revokes that turn's browser access. Open never adopts a newer human control lease.

In Agent mode, `emitFile({workspace:"personal",path:"/reports/page.png",bytes:await page.screenshot(),contentType:"image/png"})` proposes a screenshot. Every file requires `workspace: current|personal`. The same helper accepts any file bytes, including empty files. It copies `Uint8Array` or `ArrayBuffer` input at emission. Paths are canonical paths inside the chosen workspace. There is no default browser output folder. Ask mode refuses emitted files before reserving storage, with status `errored` and reason `agent_required`.

In a web session, files the page downloads during a successful command come back as `downloads` and become pending files at `/.system/downloads/<normalized name>` in the current workspace, in the same call and limits as emitted files. A bad download is dropped alone with a line in the model text; `downloadsDropped` adds one line. Ask mode refuses them with `agent_required`. The `ai-chat-agent` skill has the details.

Keep the source chat, loaded browser page, and output destination separate. A team page may produce a personal screenshot. Check the session owner, exact lease and readable source in the session's workspace, then check the output workspace. Each receipt keeps the original chat and membership lifetime; source removal or archive blocks unfinished output and agent retries. Completed files remain available through normal human review. Eight-file and 8-MiB limits cover both destinations together.

The shared writer validates the whole output list, then creates items one at a time. Valid editable UTF-8 becomes normal private text through sealed pending states. Other content stays exact stored bytes. Name collisions get bounded suffixes. A later item failure or Stop keeps earlier completed files and reports a partial result. Completed files follow normal Save, Discard, and expiry rules; browser closure and retry-receipt cleanup do not delete them.

Execution stores raw browser observations only in the current turn's map, keyed by tool call ID. Its returned result has safe status, reason, tagged Files targets, and optional capped display text under `metadata.debug` (code 4,000, result 8,000, console 2,000, page errors 1,000, error 1,000; 16,000 total; empty fields omitted). Stored `input` is still `{}` and `part.input.code` is never used by the UI. `toModelOutput` reads that map without I/O and records the final fixed status and reason. Private text uses content parts. Before every provider call, the server rechecks the exact captured source and lease. Expired text and recovery keep only the safe result with a false access check; private data and old lease closures are dropped. Images are removed. Later SDK steps cannot restore private text from their original messages. A completed call keeps its status when its old page observation expires. Text markers carry no authority. Chat storage, history replay, and titles never rebuild raw observations or image bytes, and `file_stored` never sends debug text to the model. Old results without debug remain valid.

`view_image({workspace,path})` reads a PNG, JPEG, WEBP, or GIF in either mode without a browser session. Its strict object schema requires a Files path and `workspace: current|personal`. Execute checks the chosen file and the original chat before and after the bounded read, then keeps pixels in the same private turn map. Screenshots are ordinary Files output; call `view_image` to inspect them. Read text with Bash and other bytes through `execute_code` and `/api/v1/files/read-bytes`. See `ai-chat-agent` for limits and provider conversion.

Send, Edit, Retry, and Regenerate capture the current saved browser intent. Automatic queue drain keeps each queued intent; explicit Resume captures it again. The original persisted user message, membership lifetime, provider choice, and policy revisions grant authority. Status can discover or Open can create an authorized browser later in the turn. Runner checks refresh metadata but never silently adopt a human's changed lease. Only the turn's own checked action may advance it. Takeover, End, Off, or stale authority removes browser tools; other tools and the final reply continue.

Every dispatched call has a durable identity for its source message, tool call ID, and operation hash. Exact retries return only a safe receipt. They never replay an action or rebuild old page text. Lost replies stay unresolved until receipt recovery proves cleanup or provider closure. Cleanup holds its own scope, so deleting a chat or source message cannot strand a running command.

Files paths use `/` as the workspace root. A Files output at `/tmp/report.png` is a normal reviewable file. Bash `/tmp` is separate per-thread scratch; its Files counterpart is `/home/cloud-usr/w/<organization>/<workspace>/tmp/report.png`.

# UI

- Files panel (`files-browser.tsx`): Start card with source picker, status/controls/meta, live viewer and renew loop. Editor/browser split keeps the editor mounted across toggles; focus collapses it; popout is a session-bound child route with attach → take → close transfer.
- Web panel (`web-browser.tsx`): Browser provider and Browser settings stay available before Start. Cloud shows the paid Start card, up to eight tabs, and the selected-tab viewer. My browser shows Connect, exact confirmation, and Pause/Resume/Reconnect/Disconnect without video. Manage saved data only owns cloud cookie listing and clearing. It never resets blocked sites or provider choice. A dropped viewer reconnects with a new viewer ID and needs human Take control again. Saved-site listing uses `data-sites-state="hidden|confirm|loading|loaded"` and moves focus to the surviving heading or input when a control disappears.
- A new socket hello replaces the previous socket's control. The newest control generation wins across the query and stream; a completed human handoff wins over pausing at the same generation. Grant renewal depends on session/viewer identity, so Take and metadata updates cannot restart its timer.
- A session-ended socket close retires that exact app session through `end_browser`, so idle expiry returns to Start even when it stops the renewal timer first. A viewer-moved close leaves the session live.
- Selecting another file or folder, or leaving the Browser view, never ends a file session. The panel unmounts, so its viewer disconnects and the runner stops the screencast. The session still counts browser minutes until End or the 5-minute idle limit, and watching never extends idle. `FileNodeView` keeps the chosen view in the URL `fileView` param. Browser Back, a reload, or a shared link reopens `Browser`; opening the file again from the tree starts on its default view, and `Open <name>` opens `Browser`. On another HTML file the Browser view shows "A browser is open on <name>." with `Open <name>` (dispatches `files::open_browser`) and `End it`, like the web-browser card. Until `current_browser_session` answers, the panel shows `Loading…` instead of Start, because Start would get `Browser busy` from a session live on another file. `current_browser_session` returns the live path, so the name follows a rename. When the owner can no longer open the session's file (archived, deleted, access removed), `current_browser_session` hides it. The next `start_browser` then runs `authorize_live_browser_session`, which ends it with `access_lost`, and the new start takes the slot. The opener keeps each popout window and its handoff step in a module store (`useFilesBrowserPopoutStore`), and one window listener reads the child's messages, because the panel unmounts when the user leaves the file or its Browser view. A panel that mounts again while the popout holds the viewer shows "Viewing in a popout window." and attaches no second viewer, so it cannot take control from the popout. `Dock in Files` dispatches `files::open_browser` for the session's file, which reopens its Browser view (a view that already shows the browser, such as Code + Browser, stays). The panel that mounts then attaches the viewer and sends the dock ack. Dock still times out when the opener tab is not on the Files route. The popout receives the opener's selected chat through messages checked against origin, opener, and session id.
- Browser and file tool cards show safe status and authorized Files links marked `Pending review` or `Saved`. Missing or denied targets show unavailable. File links use normal Files navigation. The browser card may also render capped display sections (Code, Result, Error, Console, Page errors) from `metadata.debug`. Raw lease JSON, provider/session IDs, inline images, and screenshot bytes never render in these cards.
- Private and saved File details share an image preview with expanded Pending rows. Save shows required private folders and submits their exact reviewed versions with the selected image. Other images remain pending. Discard removes only reviewed proposals. Saved origin links keep old chat targets usable after private receipt cleanup, with current Files ACL checks.
- Stop aborts the chat. Receipt recovery drains any accepted work; an aborted HTTP reply alone does not release a browser command.
- The web choice stays frozen per queued message. Cloud discovery and creation remain available when that saved choice allows them.

# Limits

Each owner/workspace has one file slot and one web slot, with two cloud sessions per user, two per workspace, four per organization, and ten per deployment. Web holds up to eight tabs. Each slot runs one command at a time: 30 seconds per snippet, 20 browser operations per turn. A cloud run claims a 30-second deadline. Cloud management calls claim up to 120 seconds. File limits: 20 minutes total, 5 idle minutes, 60 commands, 32 loads, 8 MiB total HTML, and 900,000 bytes per HTML source. Web limits: 60 minutes total, 9 idle minutes, and 120 commands. Viewing never extends idle. File output allows eight files and 8 MiB per call. Trusted screenshots allow PNG/JPEG, 2 MiB, 16 million pixels, and 8192 pixels per edge. Daily limits are 30 file starts and 100 draft captures per workspace, and 50 successful web starts per user. Remote limits are in [Playwriter](references/playwriter.md).

# Runbook

- Env (Convex deployment): `BROWSER_RUNNER_URL`, `BROWSER_RUNNER_SECRET`, `AI_CHAT_BROWSER_ENABLED=true`. Runner secrets live in Wrangler, never in app code: `BROWSER_RUNNER_SECRET` and `BROWSER_PROFILE_KEY` are required. Changing `BROWSER_PROFILE_KEY` makes every saved profile unreadable (`profile_unreadable`). Runner vars: `BROWSER_RUNNER_DISABLED` (kill switch; close and `profile-delete` still work), `BROWSER_WEB_DENIED_HOSTS`, and `BROWSER_APP_ORIGINS` (CORS for computer uploads; empty in production, so computer uploads fail there until it is set).
- Child bundle: retain class/function names with `--keep-names` and retain identifier names by using only `--minify-whitespace --minify-syntax`. Playwright serializes its screenshot helper into the page with `__name`; renaming that helper breaks `page.screenshot()`. Follow the [external scratch build commands](../../../packages/browser-runner/README.md#develop--deploy). The generated-bundle regression runs the actual helper and checks caret hiding and cleanup.
- Deploy the runner from `packages/browser-runner`: `vp env exec pnpx wrangler deploy --env dev`. Do not use `pnpm run deploy -- --env dev`: pnpm passes the `--` through, wrangler drops the env, and the deploy targets the top-level (production) Worker. Tail it: `vp env exec pnpx wrangler tail bonobo-senate-browser-runner-dev`.
- Every close from Convex sends a short snake_case `reason` (`human_end`, `agent_close`, `start_orphan`, `access_lost`, `member_removed`, `account_deleted`, `profile_listed`, `profile_site_cleared`, `profile_cleared`). The runner only logs it, as `close_request` with `by` and `saveProfile`. It is not the usage receipt `reason`, which is the runner's own close cause (`close`, `expired`, and so on).
- Deploy order when the runner body or reply shape changes: flag off, wait until no session is live, deploy the runner, push Convex, flag on. The runner rejects unknown body fields, so old Convex with a new runner (or the reverse) fails while they differ.
- Production `BROWSER_WEB_DENIED_HOSTS` is empty on purpose (owner decision, 2026-09-23): production denies no host. Dev keeps its list (localhost, `bonobo-senate.com`, the dev Convex and Clerk hosts, our Workers).
- Accepted host policy: production does not block Press's own hosts for either web provider. A signed-in cloud profile or the user's native Playwriter profile lets the agent act as that member in every organization they can access, beyond the chat's workspace. This can bypass workspace agent rules or pending-change review through normal Press page controls. A member can add Press to "Sites the agent may not use"; those blocks remain best effort. Do not add mandatory host blocks or extra approval steps without a new product decision.
- Convex pushes through the normal `convex dev` watcher. The browser feature flag blocks tools and new work when off. Checked status, close, profile-delete, and receipt status/fence/ack calls still reach the runner, so cleanup and billing can finish during an update. They still require the runner URL and secret. Viewer and upload grants stay off.
- Billing needs no new Polar meter: `browser_usage` goes out as the shared `press_usage_event` with the app name in `metadata.name`. No code checks the meter; confirm a settled session shows in Polar during QA.
- Live QA: open an HTML file in Files, Start, take control, drive the page, resume, then ask the Files agent to inspect it. Stay inside the 5-minute idle window or re-Start. The Playwriter recipe lives in `../app-playwriter-harness/references/files.md` under "Shared Cloud Browser End To End". Web mode QA (address, popups, agent switch, busy, billing readback, second identities) lives in `../app-playwriter-harness/references/web-browser.md`.
- Stream QA: check two viewers, slow delivery, a static page, reload, viewport changes, held-input handoff, and recovery after agent screenshots and tracing. Use at least 20 native counter clicks in a visible tab. Measure the time from each click to the changed image loading and report median and p95; this is not screen paint. Aim toward 100 ms, with p95 at or below 500 ms.
